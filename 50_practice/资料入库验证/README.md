## 实验目标与边界

验证本地单进程的 PDF 与下载 AI 总结配对入库：重复不多收、失败能恢复、冲突不隐藏、旧材料不覆盖。
本人决定身份判断、恢复依据、停止条件和验收证据；具体设计在实验前写出，不预先给出完整答案。

- 故障注入只使用复制件或合成样本，不接触正式归档、真实收集箱或下载原件。
- 实验样本中的原文和个人笔记也要留下前后对照，不能把“只是副本”当作覆盖理由。
- 身份不明时保留不确定性，不能为跑通流程而强行配对。
- 实验不自动移除任何文件；正式应用仍执行根目录[agent.md](../../agent.md)的配对、核验与迁移规则。

## 五个练习场景

以下是练习要求和预期证据，尚未执行；通过标准描述可见结果，不替本人规定内部实现。

| 练习场景 | 预期结果 | 应保留的验收证据 |
| --- | --- | --- |
| 同文件重复输入 | 重复输入后不产生第二份相同归档 | 两次输入记录、归档数量和文件校验值对照 |
| 同标题不同内容 | 不仅凭标题合并，不静默覆盖；无法判明的材料继续待处理 | 两份内容差异、身份判断理由及最终去向 |
| 复制后、写META前失败 | 再次运行能识别实际进度并安全恢复，不出现重复归档或虚假完成 | 中断位置、恢复前后目录与META对照、实际恢复操作 |
| PDF与总结身份冲突 | 冲突明确可见，停止不可靠配对，保留两份输入 | 冲突字段与正文依据、待处理记录、输入保留情况 |
| 原文与个人笔记保护 | 已存在的原文、AI总结和个人笔记不被覆盖 | 运行前后校验值、差异检查和新增产物清单 |

五个场景都要有实际证据；单次成功、未报错或AI口头确认不能代替核验。
每个场景可以失败，失败要写明影响范围和未解决的问题，不删除失败记录。

## 操作顺序

1. **本人先预测与决策**：写出预期结果、关键判断、准备核对的证据，以及什么情况应停止。
2. **AI搭建外围**：根据本人方案协助准备复制或合成样本、必要代码与检查方法；帮助内容逐项记下。
3. **运行并记实**：先记输入和条件，再运行；保留实际变化、偏差、失败原因和修正后的复验。
4. **换未教过的样本验收**：改变材料或失败条件，先由本人解释与处理，再检查结果；不照抄练习答案判通过。
5. **小批真实应用**：实验与独立验收取证后，另列少量真实材料清单，依根规则核对、复制、核验及处理原位置。

说明、代码、报告和日志平铺；测试必需的输入／输出结构，在实际实验时按最少需要创建。
需要并实际生成后才建文件、补链接；不预建空脚本、空日志或不存在的产物入口。

## 独立验收怎么记

练习用于发现与修正问题，验收另换未参与讲解和调试的样本或条件。
验收前记录允许使用的帮助；本人先说明判断依据，AI再核对证据。
如果AI给出了关键决策或修复方案，结果可记为辅助完成，随后另换样本再验收。
除结果正确，还要说明为什么这样处理、什么情况下不适用，以及失败后哪些证据可信。
验收结论只覆盖实际测试范围，不写成“所有故障均可恢复”。
