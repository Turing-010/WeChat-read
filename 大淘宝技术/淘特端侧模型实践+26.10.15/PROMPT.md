# 淘特端侧模型实践：Prompt合集

## 1. 淘特端侧用户实时购物意图分类与关键词提取 System Prompt

### Prompt原文

````text
"根据用户行为序列判断购买意图并提取核心关键信息
意图分类:
闲逛:无主动购物信号,或跨多个无关品类随意浏览无场景主线
比价犹豫:同品类内商品对比
场景购物:同一大类下跨子品类围绕统一场景选购(如厨房/露营)
类目说明:
序列中 cat:大类.子类.孙类 为商品类目层级,首段为顶级大类。
判定参考:多个无关大类→闲逛;同一大类跨子类→场景购物;同一完整类目重复→比价犹豫
输出格式:
- 闲逛: 仅输出\"闲逛\"
- 比价犹豫: 输出\"比价犹豫|关键词1;关键词2;...\"
- 场景购物: 输出\"场景购物|关键词1;关键词2;...\"
关键词规则:
- 3-6个,首位为主品类(比价犹豫)或主场景(场景购物)
- 简短名词或形容词,2-6字\n- 按重要性降序排列"
````

### 使用步骤

1. 将上述文本作为端侧模型（如微调后的 `Qwen3-0.6B`）的 `System Prompt` 固定前缀（可配合 Prefix Cache 缓存）。
2. 在 `Content Prompt` 中传入经白名单过滤和规则触发的用户实时行为序列（含商详页/首页停留时长、商品标题、价格及 `cat:大类.子类.孙类` 类目编码，例如累计 $\ge 3$ 个商详 PV 时触发）。
3. 解析模型输出字符串，按 `|` 与 `;` 切分意图类别（`闲逛` / `比价犹豫` / `场景购物`）及排序后的核心关键词，分发给推荐重排或离端前权益挽留模块。

### 预期输出

单行结构化意图与关键词字符串，例如：`"比价犹豫|空调遥控器;美的;通用款;省电星;华凌"` 或 `"闲逛"`。

### 使用边界与待验证点

- 原文指出在端侧需兼顾准确率与 Prompt 长度（Prompt 越长，Prefill 阶段耗时越呈线性增加）；团队经消融实验保留了“意图分类、类目说明、判定参考、输出格式、关键词规则”五部分，剔除了用户个人 Profile，并放弃了过度简化的 Prompt 版本。
- 需配合针对性的 SFT/LoRA 微调与禁用思维链（`enable_thinking: false`）使用，直接用于未微调小模型可能出现格式偏离或幻觉。
