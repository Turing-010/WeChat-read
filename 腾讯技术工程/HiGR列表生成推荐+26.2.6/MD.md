2.1.1 痛点深⼊：为什么传统的 Semantic ID 不好⽤？
ID 纠缠
在标准 RQ-VAE 中，量化仅由重构误差驱动。这导致⽣成的 Codebook 缺乏语义拓扑结构
—— 前缀相同不⼀定代表类别相同，⽽前缀不同的物品却可能⾮常相似。对于分层规划器

残差坍塌
随着量化层数迭代，后续层级的残差向量往往趋近于零，导致深层码本实际上不承载信
息，退化为噪声，浪费了编码容量。

我们引⼊对⽐学习和全局量化约束，强制让语义 ID 的前缀成为可靠的语义锚点。
前缀对⽐约束
我们在量化器中的前 D-1 层引⼊ InfoNCE loss ，选择语义相似的 item 或共现率⾼的 item 作为
正样本，选择批次内其他随机样本作为负样本。让前缀 ID 负责 “ 聚类 ” ，将相似物品拉到同
⼀个 ID 前缀下；让最后⼀层 ID 负责 “ 区分 ” ，保持对具体物品的细粒度辨识能⼒。完美契合
我们的 “ 先规划，后⽣成 ” 的分层策略。
全局量化损失
不同于传统逐层累计的量化损失，我们针对量化器前后的编码向量和量化重构向量构造全

推理耗时长
在推理耗时极为敏感的推荐场景，传统的 “ 平铺 ” 式解码器，即把 SID 作为 token ，逐 SID 地
⽣成列表难以满⾜耗时要求，因为推理长度为 M 的列表需要推理 M*N 次（⼀个 item 由 N 位

难以建模 item 内和 item 间的关系
推荐场景中的 SID token 序列不同于语⾔模型中语义 token 序列，其有着明确的边界以及层

<c_7> ），则 <c_2> 和 <a_5> 有着明确的边界，即 <c_3> 属于第⼀个 item ， <a_5> 属于第⼆个

关系的⽂本语义 token ，但却难以捕获推荐场景中 item 内和 item 间 SID 的联系。
