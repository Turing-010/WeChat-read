六、三层治理：从 " 能跑 " 到 " 能⽤ "
链路搭起来只是第⼀步。真正让系统可靠的是  Review / Dedup / Merge 三层治理。这三层⽬
标不同、策略不同、默认⽅向也不同，但底层驱动⽅式⼀致 ——错例分析  →  规则抽象  →  评

6.1 抽取：从识别垃圾到评测驱动
在讲三层之前，得先说清楚源头 —— 经验抽取这⼀步本⾝怎么持续变好。
初版证明了 " 能抽出经验 " ，但质量参差不齐。 " 好经验 " 很难⼀次定义到位，但 " 垃圾经验 " 的特
征更容易归纳。所以我们的做法是  先研究垃圾，再反推好经验。经过⼤量标注，归纳出九类
典型垃圾特征：
1. 事实性错误—— 编造不存在的约束，把对话⾥的临时说法当规则
2. 通⽤常识—— 任何项⽬都适⽤，不体现团队特异性
3. 对话摘要—— 只复述过程，没有沉淀成可复⽤判断
4. ⼀次性  case—— 只对当前任务有效，不能迁移
5. ⽤户主观偏好—— 个⼈选择，不代表团队规范
6. 缺少上下⽂—— 不知道对应哪个模块 / 组件 / 接⼝
7. 粒度混⽤—— ⼀条经验⾥兼顾通⽤规则和  case 特定信息
8. 不可执⾏—— 只有抽象建议， Agent 看完不知道怎么做
9. 证据不⾜—— 对话⾥没有⾜够依据，模型⾃⼰推断过多

标注路径：  对候选经验做价值标注（⾼价值 / 低价值 / 垃圾）→  对垃圾做归因  →  归纳垃圾模式
