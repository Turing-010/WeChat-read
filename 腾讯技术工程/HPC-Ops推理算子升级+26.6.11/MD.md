````text
⼆、核⼼算⼦更新详解
随着⼤模型推理系统在业务侧的应⽤不断深⼊，推理优化⾯临的负载形态、精度要求和系统瓶颈
也更加复杂。为了在真实复杂业务场景中进⼀步提升推理性能，HPC-Ops 本次更新围绕两⼤核
⼼⼯程思想进⾏了全⾯升级：⼀、深度适配线上复杂负载（应对多精度计算与长短请求混排）；
⼆、多算⼦联合优化。本次更新内容主要包含以下五⼤核⼼算⼦：
1. Attention ：动态调度负载均衡，根治推理长尾延迟
线上推理存在请求长度实时波动、 batch 内长短请求混杂等特征。对于均匀长度负载，传统静态
split-kv  已经可以稳定⼯作；但⼀旦进⼊长上下⽂混合负载，静态策略就需要在长序列吞吐和短
序列开销之间做固定权衡：长序列需要更⼤的  split-kv  才能充分并⾏，短序列则只需要少量拆
分，固定策略很难同时兼顾。针对此问题， HPC-Ops 对  Attention 调度机制完成全⾯升级，将传
统固定任务划分模式，迭代为更适配动态业务的运⾏时动态调度⽅案。
该⽅案先将所有推理请求按统⼀ Tile 粒度拆分，依据全局 Tile 总量均衡分配各 CTA 任务规模，再通
过贪⼼装桶算法实现 Tile 任务极致均分，从源头杜绝计算单元负载失衡问题。在执⾏链路中，
Task Assign 模块会在每次推理前⽣成专属任务映射表，各层 Attention Kernel 依据映射表精准领
取并执⾏对应任务，最终由 Combine Kernel 统⼀合并 split-kv 计算结果，实现全流程负载均衡、
⾼效协同运算。
````

````text
2. Router GEMM ：双 BF16 重构 FP32 计算，兼顾⾼精度与⾼性能
在 MoE 路由、稀疏 Attention 等模块中，普遍存在激活为 BF16，权重为 FP32 的⾼精度GEMM 计
算。若将权重降精度参与计算，其精度难以满⾜MoE Router 、Attention Score 等数值敏感算⼦，
会直接影响模型效果；若将激活升精度⾄  FP32 或  TF32 ，则需引⼊逐元素类型转换的额外带宽
与算⼒开销，且纯FP32计算只能使⽤ CUDA Core 运算单元，硬件利⽤率受限。
针对上述问题， HPC-Ops 提出双 BF16 GEMM 组合模拟 FP32 精度的优化⽅案：离线阶段将  FP32
权重拆分为⾼位  BF16 与低位残差  BF16 两组张量，即 W ≈ W_high + scale × W_low （缩放因⼦
scale 取  1/256 ，对齐 BF16 的 8 位尾数）。推理阶段执⾏两次  BF16 GEMM 并做线性组合，激活值
全程保持  BF16 ，⽆需类型转换，且两路矩阵乘均运⾏在  BF16 Tensor Core 上，算⼒利⽤率得以
充分释放。更进⼀步，实现时我们将双路计算融合⾄单⼀  Kernel ：输⼊数据仅搬运⼀次，通过双
寄存器累加器分别缓存两路中间结果， Epilogue 阶段经⼀次 FMA 修正出⾼精度结果写出到显存，
全程⽆中间结果的  HBM 往返开销。
````

````text
3.FusedMoE ：全算⼦流⽔线重构，极致压缩推理开销

在路由与索引预处理阶段，采⽤共享内存分块统计，为每个专家预留连续显存输出区间，⼤幅降
低⼤规模  Token 输⼊场景下的索引构建成本。在 Gate-Up GEMM 计算阶段，可直接通过路由索

Warp Group 完成数据搬运与计算任务，将访存延迟掩盖逻辑从 CTA 内软件流⽔线，升级为跨 CTA
硬件调度，显著提升单 SM 可驻留线程块数量，最⼤化硬件资源利⽤率。
推理过程中，激活量化结果按专家维度紧凑写⼊显存，保障  Down GEMM ⽆缝读取、⾼效计
算，并在推理末端完成  Top-K 加权聚合。全流程通过  PDL  技术串联为⽆⽓泡执⾏链路，显著
消除频繁 Kernel 启动带来的冗余开销。
4. Fused AllReduce+Norm ：通信计算深度融合，打通张量并⾏瓶颈
针对张量并⾏场景下，通信、残差计算、归⼀化拆分执⾏导致的性能损耗， HPC-Ops 联合腾讯
⽹络平台部，创新实现 AllReduce 通信、残差相加、 RMSNorm 归⼀化的全链路融合计算，封装为
NVLink 原⽣⼀体化操作： RMSNorm(AllReduce(x) + residual, weight)。双⽅围绕通信拓扑优化、
P2P 同步机制、计算与通信融合逻辑完成协同打磨，让原本分段执⾏的离散链路，实现⼀体化、
⾼效率运⾏。
该能⼒基于  CUDA  多播 (multimem) 与 P2P 点对点技术构建，原⽣⽀持  BF16 精度与单节点多
GPU 部署环境，采⽤ Reduce-Scatter + All-Gather 的  two-shot ⾼效执⾏策略。同时针对不同推
理场景提供两套差异化实现⽅案，适配性更强：
1. ⾼吞吐版本（ fuse_allreduce_rmsnorm_high_throughput ）依托 NVSwitch 多播机制完成归约计
算，适配⼤规模  Token 的  Preﬁll 预处理场景；
2. 低延迟版本（ fuse_allreduce_rmsnorm_low_latency ）基于 Lamport P2P 机制，通过 PDL 实现
双 Kernel 重叠执⾏，适配⼩批量 Token 的 Decode 推理场景。
5. Sampler ：极致⼤算⼦融合，终结后处理性能瓶颈
针对传统采样后处理多 Kernel 串联、流程碎⽚化、冗余开销⼤的问题， HPC-Ops 推出
fused_sampler 算⼦，重构⼤模型推理后处理逻辑。该算⼦将主流框架中⼗余个零碎  Kernel 串联
实现的重复惩罚、温度缩放、 Top-K 、 Top-P 、 Softmax 、随机采样的全流程能⼒，端到端融合为
2 个核⼼ CUDA Kernel ，并封装为单⼀算⼦。针对差异化业务场景提供更加精简专⽤内核，算⼦
内可⾃动适配调度，最⼤化释放 GPU 算⼒潜⼒。本次优化的性能增益主要来⾃五⼤维度：
1. 全流程内核融合，将采样场景全局词表⼤⼩的 GPU 加载次数压缩⾄  1 次，且计算访存充分掩
盖；
````
