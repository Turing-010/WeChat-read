# 10 个技巧，让你的 WorkBuddy 比别人好用！

## 1. TL;DR

本文针对开发者与日常用户在使用 **WorkBuddy** 时高频遇到的“长对话遗漏要求或反复出错、只想聊思路却被直接改了文件、装了一堆技能反而不会选、跨模型切换导致性能下降与高消耗”等痛点，提炼出 10 个立即可用的工程化操作技巧。全文底层逻辑收敛为三件事：**一看住上下文用量**（通过右下角用量圆圈监控系统提示词、工具/子智能体、消息与 MCP/技能开销，最佳水位控制在窗口一半左右，超半及时用 `/compact` 配合外置“任务检查点”文件主动压缩或同工作空间新开会话）；**二用对模式、模型与会话**（讨论阶段开“仅问答模式”省去编辑工具定义开销，按是否需长期完整记忆开关 `Max 模式`，同一会话严禁频繁切换模型以防 Prompt Cache 失效与小窗口裁剪）；**三管住技能与偏好资产**（关掉长期不用的技能减少定义占用与选择干扰，用“增强提示词”过滤废话，分清每晚自动提炼的“记忆”与手动配置的“个性化”，并通过迁移提示词导入外部 AI 历史画像）。

## 2. 核心概念

- **上下文用量拆解（右下角灰色小圈）**：实时展示当前会话已用 Token 比例与上限（如 `4.9% · 49.4K/1000K`），其内部构成包含四块：**系统提示词占用 + 工具及子智能体占用 + 对话消息占用 + 连接器、MCP 及技能占用**。
- **仅问答模式（Ask 模式）vs 默认执行模式**：位于对话框 `+` 号旁模式入口；开启后**不加载部分执行和文件编辑相关工具**，既防止讨论思路时误改本地文件，又削减了工具定义带来的固定上下文开销。
- **Max 模式（完整上下文保留开关）**：位于模型选择下拉顶部；打开 Max 时**不压缩、保留完整上下文**（适合需频繁引用前文讨论、文件状态与复杂约束的任务，但消耗更多积分）；关闭 Max 时系统会在适当时机自动压缩上下文以降低窗口占用。
- **记忆（自动画像）vs 个性化（手动规则）**：
  - **设置 → 记忆**：WorkBuddy **每天晚上自动从当天对话历史中提取**有价值的长期信息（如专业背景“用户熟悉上下文工程”、表达习惯“用户偏好总分总结论”），无需手动维护。
  - **设置 → 个性化**：用户**手动指定**的全局配置，包含回复风格语调（专业严谨、亲和友善、直言不讳、高效务实）、是否显示加载欢迎语、是否展示文件变更过程详情，以及应用于所有对话的自定义指令。

## 4. 关键要点与机制详解

### 4.1 十大操作技巧速查与底层机制全表

**核心主张**：WorkBuddy 的大多数“变笨、乱改、费积分”现象并非底层模型退化，而是工具/技能定义、长历史与模型切换破坏了上下文信噪比与缓存机制。

| 技巧编号与名称 | 入口位置 / 命令 | 适用场景与触发信号 | 底层运作机制与关键操作规范 |
|---|---|---|---|
| **技巧 1：查看「上下文用量」** | 对话框右下角灰色小圈 | 对话聊久后 Agent 开始遗漏要求、反复出错，需判断是能力问题还是窗口将满 | 点开可查系统提示词、工具/子智能体、消息、连接器/MCP/技能四项占用（如 `4.9% · 49.4K/1000K`）；🔥 **产品经理建议最佳状态在用量一半左右，超过一半就应考虑压缩或新开任务** |
| **技巧 2：「增强提示词」** | 对话框右下角小闪光图标 | 担心手写指令含糊、有歧义或废话过多消耗 Token | 点击后 AI 自动将原始诉求改写得更干净、聚焦、少废话，让用户聚焦于“要完成什么目标” |
| **技巧 3：切到「仅问答模式」** | 对话框 `+` 旁模式入口 → 仅问答 `Ask` 开关 | 梳理选题、讨论方案、分析问题、找灵感、正式执行前明确需求（不想让 AI 直接改文件） | 🔥 **不加载部分执行和编辑相关工具**，既从机制上阻断误改文件，又减少了工具定义占用的固定上下文开销 |
| **技巧 4：关闭长期不用的技能** | 技能管理页（关掉开关即可，不必删除） | 装了很多技能后上下文莫名偏高，或几个相似技能导致模型选错、纠结 | **每个已启用技能的定义本身都要发给模型看**；装得越多不仅白吃一大块窗口，还会加大模型路由选择干扰。只保留当前场景所需，用时再开 |
| **技巧 5：善用 `Max 模式`** | 模型选择下拉菜单顶部开关 | 需权衡“跨多轮保留完整细节”与“控制积分消耗” | **打开 Max**：不压缩、保留完整上下文（适合频繁引用前文讨论、文件状态与复杂约束的任务，耗积分高）；**关闭 Max**：适时自动压缩（适合独立任务或已积累大量无用讨论） |
| **技巧 6：`/compact` 手动压缩** | 对话框直接输入斜杠指令 `/compact` | 任务未跑完但对话已很长、模型变慢变笨，且不想新开会话 | 让模型主动总结前文并替换原始对话记录以腾出窗口（比满窗被动裁剪更可控，但仍有损）；🔥 **压缩前务必先让 Agent 将 6 项「任务检查点」写入工作空间文件** |
| **技巧 7：单会话勿频繁切模型** | 模型选择下拉菜单 | 想在同一对话框里混用低 Token 模型与高 Token 模型 | 🔥 **反常识大坑**：频繁切模型会导致 ① **提示词缓存（Prompt Cache）失效**（缓存与具体模型及服务机制绑定，切模型无法复用）；② **上下文窗口不一致触发强制压缩或裁剪**（从大窗口模型切到小窗口模型）。同一任务尽量用一个模型跑完；必切时先 `/compact`；试效果则开新会话 |
| **技巧 8：新开会话 vs 留原会话** | 新建会话 + 左下角「选择工作空间」下拉 | 判断长对话何时该断舍离、何时该续聊 | **开新会话 3 信号**：① 圈圈快满（如 `900K/1000K`）；② 陷入死循环反复出错；③ 两件事毫无关联。**留原会话 2 信号**：① 同一任务连续追问；② 前序文件与状态需延续。🔥 **铁律：新会话务必开在同一工作空间里**（“工作台没变，换个更清醒的脑子”） |
| **技巧 9：分清「记忆」与「个性化」** | `设置 → 记忆` vs `设置 → 个性化` | 配置个人偏好与全局指令时感觉混乱别扭 | **记忆**：每晚自动从当天对话提取长期有价值信息（背景、习惯、偏好）；**个性化**：手动指定回复风格（专业严谨/亲和友善/直言不讳/高效务实）、加载欢迎语开关、文件变更详情开关、全局自定义指令 |
| **技巧 10：迁移外部 AI 记忆** | 复制官方迁移提示词 → 原 AI 导出 → 导入 WorkBuddy | 长期使用其他 AI 产品，不想在 WorkBuddy 从零磨合个人画像 | 复制迁移提示词让原 AI 整理一份「关于你的记忆总结」，人工检查无误后粘贴导入，两次复制粘贴完成画像冷启动 |

### 4.2 重点规程详解：执行 `/compact` 前的「六项任务检查点」外置法

**核心主张**：主动摘要压缩（`/compact`）虽比满窗截断可控，但本质仍是有损总结，必须通过“先落盘工作区文件、再执行 `/compact`”实现无损状态接力。

- **标准操作规程（SOP）**
  1. 当观察到右下角上下文圈圈超过 $50\%$ 或模型响应变慢时，暂停直接发新需求。
  2. 先向 Agent 下达指令，要求其整理一份包含以下 **6 项核心要素的「任务检查点」** 并写入当前工作空间的本地文件中：
     - **当前目标**
     - **已经完成的内容**
     - **重要约束**
     - **修改过的文件**
     - **尚未解决的问题**
     - **下一步动作**
  3. 确认检查点文件写入工作空间后，在对话框发送 `/compact` 触发上下文主动压缩，或在**同一工作空间**下开启新会话并让新会话直接读取该检查点文件继续推进。

## 6. 踩坑与教训 / 可迁移的设计原则

### 常见踩坑与应对

| 错误做法 | 失败表现或原因 | 原文应对策略 |
|---|---|---|
| **只想讨论选题或方案时直接用默认模式开聊** | 模型一言不合直接调用编辑工具修改本地文件，且白白携带大量执行工具定义消耗上下文 | 讨论阶段在 `+` 号旁模式入口切到「仅问答模式（Ask）」，卸载部分执行/编辑工具定义 |
| **把技能库里的技能全装上并长期保持开启** | 每个技能的定义文本每轮都要发给模型，既吃掉大块窗口，又导致相似技能互相干扰使模型选错 | 在技能管理页把长期不用的技能关掉（无需删除），只保留当前场景所需，随用随开 |
| **同一会话里为了省钱反复在大小模型间来回切换** | 破坏模型绑定的提示词缓存（Prompt Cache）导致重算更贵，且从大窗口切向小窗口模型会触发被动压缩裁剪丢信息 | 同一任务锁定同一模型跑完；非切不可时先执行 `/compact`；想对比不同模型则在同工作空间另开新会话 |
| **长对话直接裸跑 `/compact` 而不做状态落盘** | 摘要过程弱化或漏掉特殊约束、已改文件清单与中间状态，压缩后模型“失忆”犯错 | 执行 `/compact` 前，先让 Agent 将 6 项「任务检查点」写入工作空间文件，靠外部文件系统兜底有损摘要 |
| **聊完全无关的新话题仍赖在旧会话，或开新会话时切丢工作空间** | 旧会话里上百 K 的历史变成纯噪声拖慢推理；而切丢工作空间又导致新会话读不到项目文件 | 跨话题、死循环或窗口近满（如 $900\text{K}/1000\text{K}$）果断在**同一工作空间**开新会话（换脑不换台） |

### 可迁移的设计原则

- **“工作空间文件落盘 + `/compact`”的有损压缩对冲范式**：任何基于 LLM 总结的上下文压缩（`/compact`）本质都是有损的。工程上最稳妥的做法是把确定性状态（目标、已完成、约束、已改文件、待办、下一步）先固化到工作区磁盘文件，再压缩会话历史——用磁盘的无损持久性弥补上下文摘要的有损性。
- **工具与技能定义的“按需挂载（Just-in-Time Loading）”**：上下文窗口不仅是对话历史的容器，更是系统提示词、MCP 工具与 Skill 定义的共享预算池。通过模式切换（如 Ask 模式卸载编辑工具）和技能开关裁剪非活跃工具定义，是从源头提升推理专注度与降低首包开销的低成本手段。

- **原文三句话总纲锚点**：“1. 看住上下文用量；2. 用对模式和会话；3. 别让不必要的技能和废话吃掉你的窗口。”

## 8. 复习卡片

WorkBuddy 对话框右下角的「上下文用量」圆圈包含哪四部分开销，产品经理建议的健康水位是多少？::包含系统提示词占用、工具及子智能体占用、对话消息占用，以及连接器、MCP 及技能占用四部分；最佳状态是用量控制在窗口的一半（50%）左右，超过一半就应考虑压缩上下文或新开任务。
为什么在只讨论思路或梳理方案时应该开启「仅问答模式（Ask）」？::因为仅问答模式不仅能防止 Agent 直接动手修改本地文件，还不会加载部分执行和编辑相关的工具，从而减少工具定义带来的固定上下文开销，让模型更专注于分析讨论。
为什么装太多技能会导致 WorkBuddy 变慢或选错技能，正确的管理方式是什么？::因为每个启用技能的定义本身都要发给模型阅读，装得越多不仅白吃一大块上下文窗口，还会干扰模型判断该调用哪个技能；正确做法是在技能管理页将长期不用的技能关掉（无需删除），只保留当前场景所需，用时再打开。
既然 `/compact` 可以主动压缩上下文，为什么复杂任务在执行 `/compact` 前还要先写一份「任务检查点」文件？::因为 `/compact` 是用模型总结替换原始对话记录，本质仍是有损压缩，可能弱化部分细节、特殊约束和中间状态；先让 Agent 将“当前目标、已完成内容、重要约束、修改过的文件、尚未解决的问题、下一步动作”写入工作空间文件，压缩后即可从文件无损重读状态。
为什么在同一会话里频繁切换不同模型反而会导致性能下降甚至信息丢失？::原因有二：一是提示词缓存（Prompt Cache）通常与具体模型及服务机制绑定，切换模型后原有缓存未必能复用；二是不同模型支持的上下文窗口长度不同，从大窗口模型切到小窗口模型可能直接触发被动压缩或裁剪。
什么信号出现时应该果断新开会话，新开会话时为什么要保持在「同一个工作空间」？::当上下文圈圈快满（如 `900K/1000K`）、模型陷入错误死循环、或准备聊毫无关联的新话题时应开新会话；保持在同一工作空间是为了让新会话仍能直接读取项目文件与背景资料，做到“工作台没变，但给任务换了一个更清醒的脑子”。
WorkBuddy 设置中的「记忆」与「个性化」有什么本质区别？::「记忆」是系统每天晚上自动从当天对话历史中提取并积累的长期用户画像（如专业背景、表达偏好），无需手动操作；「个性化」则是用户手动指定的全局配置（如回复语调风格、加载欢迎语开关、文件变更详情开关及全局自定义指令）。
