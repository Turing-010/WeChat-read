Run - To - Completion 线程模型
在 Fuse  使⽤场景中，传统线程由 libfuse  创建，这类线程不具备 libco  协程环境，这就导

程，这会造成严重的资源浪费，同时还会带来⾼昂的线程切换开销。为了实现 Run - To -

深度定制的 ultra - core  异步⽹络组件
⾸先我们将 libfuse  读接⼝改造成异步形式，完成⾮阻塞化改造。改造后，线程不会因为等

的接⼝调⽤逻辑，引⼊ ultra - core  异步回调机制，让读请求的发起与结果处理解耦。线程发

````text
⽼版本 WFS  在数据传输过程中存在⼤量的 CPU  拷⻉操作，造成了严重的性能损耗，性能
优化的关键是如何做到零拷⻉。
客户端零拷⻉
客户端数据传输链路中总共存在 5  次拷⻉，流程为内核 socket  →  userspace  →  反序列化
→  缓存 →  fuse  buffer  →  / dev / fuse 。每⼀次拷⻉都需要消耗 CPU  资源，拖慢了数据传输
速度。通过 ultra - core  ⽹络组件配合 splice  接⼝，结合⾃定义⽹络协议格式，实现了零拷
⻉传输。数据传输流程简化为内核 socket  --- splice  move ---> / dev / fuse ，直接省略了
⽤户空间的多次拷⻉操作。
服务端零拷⻉
服务端数据传输链路中总共存在 3  次拷⻉，流程为内核 disk  →  userspace  →  序列化 →
内核 socket 。同样，多次拷⻉导致服务端 CPU  负载居⾼不下，限制了带宽的提升。采⽤
sendfile  接⼝，彻底消除了⽤户空间和内核空间的数据拷⻉。数据从内核 disk  通过 DMA
传输到 page  cache ，再通过 DMA  直接传输到 NIC 。整个过程完全由 DMA  完成，不占⽤
CPU  资源，⼤幅降低了服务端的 CPU  消耗。
````
