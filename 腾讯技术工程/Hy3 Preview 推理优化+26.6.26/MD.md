2.5 MTP 和异步调度优化
问题
传统异步调度基于 " 每轮稳定⽣成  1 个  token" 的假设，在  GPU 计算时让  CPU 提前准备下⼀
轮输⼊，从⽽掩盖  CPU 耗时。然⽽，多层  MTP 引⼊了动态接收长度 —— 下⼀轮的序列长

强制同步，将结果拷回  CPU 再准备下⼀轮输⼊，导致  CPU 准备阶段只能与  MTP 层  Forward
重叠；⽽  MTP 层计算极快，⽆法充分掩盖  CPU 耗时。
⽅案
核⼼思想：  解除  CPU 对真实接收长度的同步依赖 —— 数据准备阶段⼀律按最⼤接收长度更新
状态并组装下⼀轮输⼊；在下⼀轮实际计算前，再以上⼀轮的真实验证结果修正计算所依赖的
关键值。由此， CPU 可提前⼀轮完成准备与  Launch ，⽆需阻塞等待  GPU 计算结果。
收益：减少 decode 间  5 ～  10ms CPU ⽓泡，  端到端提升  10% ～ 20%  性能

1. Token Position-Decay （位置衰减策略）
洞察：因果架构中，序列头部  token 参与了所有后续聚合计算，误差会逐层递归放
