# 调度伪代码
class AgentScheduler:
    def __init__(self):
        self.queue = FileQueue("storage/feedbacks/")
        self.tools = ToolProber(["codex", "gemini-cli", "claude"])
        self.state = JsonStateManager("storage/state/")
    def run(self):
        while True:
            task = self.queue.poll()
            if not task:
                time.sleep(10)
                continue
            tool = self.tools.get_available()  # ⾃动选可⽤⼯具
            try:
                result = tool.execute(task.prompt, task.workspace)
                self.state.update(task.id, status="done", output=result)
            except QuotaExhausted:
                self.tools.cooldown(tool, duration=300)  # 5  分钟冷却
                self.queue.requeue(task)  # 重新⼊队，换⼯具执⾏
            except Exception as e:
                self.state.update(task.id, status="failed", error=str(e))
调度层做四件事：
1. 接收任务：⽤户反馈进来，写⼊⽂件队列
2. 分发执⾏：轮询队列，调⽤  CLI 执⾏
3. 状态管理：记录每⼀步的输⼊输出，持久化到⽂件
4. 失败切换：某个  CLI 配额⽤完，⾃动换下⼀个
选型极其简单：⽂件系统存储  + 轮询调度  + JSON 状态管理。 不是在论证 " ⽂件系统⼀定优于
数据库 " 。对⼀个还在⾼速迭代的  Agent 系统来说，⽂件系统的好处很实际：出问题直接让  AI
看⽂件，不⽤查数据库；⽅便  Git 版本控制；本地和⽣产环境更⼀致。
SDD ：让  AI 的每⼀步都有据可查
这套系统⾥最核⼼的概念是  SDD （ Spec-Driven Development ）。
很多⼈把  SDD 理解为 " 先写⽂档再开发 " 。但在  Agent 场景⾥， SDD 更重要的作⽤是：把⼀件
事从模糊想法逐步转成可执⾏单元，并且把这个过程完整留下来。
每个需求处理完会留下⼀组⽂档：
storage/feedbacks/2026-01-15/20260115-143021-a1b2c3/
├── sdd/
