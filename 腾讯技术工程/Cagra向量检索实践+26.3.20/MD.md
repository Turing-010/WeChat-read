引⾔
在当今的互联⽹服务架构中，向量检索技术已成为推荐系统、搜索引擎、内容匹配等核⼼业务
场景的关键组件。随着深度学习模型的⼴泛应⽤，如何在海量向量数据中⾼效进⾏近似最近邻
（ Approximate Nearest Neighbor, ANN ）搜索，直接影响着在线服务的⽤户体验和业务效
果。
Cagra （ CUDA Accelerated Graph-based Retrieval Algorithm ）是  NVIDIA 推出的基于  GPU
加速的图索引  ANN 算法，也是  RAPIDS cuVS 库的核⼼组件之⼀。与过去业界⼴泛使⽤的传
统  CPU-based ANN 算法（如  HNSW 、 IVF 等）相⽐， Cagra 充分利⽤了  GPU 的强⼤并⾏计
算能⼒，在保持⾼召回率的同时，能够提供显著更⾼的吞吐量，满⾜不同业务对⾼性能、低成
本的极致要求。
本⽂将分享我们团队如何攻克多项⼯程难题，在业界率先将  Cagra GPU 图索引⼤规模应⽤于
核⼼线上推荐业务的技术实践与架构演进。
Cagra 算法原理与核⼼优势
核⼼技术原理
Cagra 采⽤基于图的索引结构，其核⼼思想是将向量数据构建成⼀个近似   - 近邻图（-NN
graph ），然后在查询时通过启发式图遍历算法快速定位最近邻向量。
与传统的  HNSW 算法相⽐， Cagra 的结构设计针对  GPU 架构进⾏了深度定制，主要区别在
于：
1. 单层图结构： Cagra 采⽤单层图设计，摒弃了  HNSW 复杂的的多层分层结构，更利于显
存的连续访问。
2. 固定出度： Cagra 每个节点的出度固定，⽽  HNSW 的出度只需⼩于等于给定值，这使得
GPU 上的内存分配和线程调度更加规整。

3. 批量化检索： HNSW 每次选取⼀个点遍历邻点并加⼊候选集；⽽  Cagra 每次会同时从候

为了在  GPU 上实现更⾼的并⾏度与准确率， Cagra 在构建图时需要权衡两个关键指标：
全图连通性：由于采⽤单层图设计且检索起始点选取较随机，必须确保所有节点双向连
通，这是保证最终准确率的前提。
遍历效率优化：在⾼维数据图的遍历中， CPU 侧通常依赖  hubs （⾼度连接的节点）来加
速收敛。但在  GPU 场景下策略截然相反： GPU 采⽤分批处理机制，访问节点集合扩散得
越快，越能发挥并⾏优势。因此，减少对  hubs 的重复遍历、让节点访问更加均匀分散，
反⽽能加快查询收敛速度。
线上化改造与⼯程实践
由于  Cagra 诞⽣之初更侧重于离线⼤规模场景，为了将其适配到严苛的线上⾼并发服务中，
我们与  NVIDIA 技术团队进⾏了深⼊的探讨，并对底层逻辑进⾏了⼤量优化。
1. 适应⽣产环境的建图优化
原论⽂采⽤  NNDescent 算法构建正向图，反转得到反向图后合并，再根据 “2 跳可达点数 ” 对
边进⾏排序和裁剪。然⽽在实际应⽤中，这种建图⽅式过度依赖⼤容量的  Pinned Memory
（锁页内存），难以在标准的容器化⽣产环境中规模化部署。
为此，我们设计了渐进式⼦图优化⽅案：  ⾸先随机构建连通图，通过多次⼩范围遍历筛选出
⼦图，再对⼦图执⾏与论⽂类似的建图流程，逐步优化全图结构。最后辅以⼀轮连通性调整，
在⼤幅降低内存依赖的同时，达到了与全图  NNDescent 相同的准确率效果。
2. 极致的性能表现
在我们的⽣产级数据集（千万级规模，⾼维向量）测试中， Cagra 展现出了惊⼈的性能优势：
建库性能：在保证召回率    的前提下，传统  HNSW 算法需要耗费数⼗分钟甚⾄⼩时
级的时间，⽽  Cagra 将建索引时间缩短⾄原来的  1/30 以下（仅需⼏分钟）。
检索吞吐：测试表明，当  Batch Size 增加时， Cagra 在同等硬件成本下可以获得远超
CPU 的  QPS 。 Batch 越⼤， QPS 提升越显著，完美契合⾼并发的推荐场景。
分布式向量检索系统的架构演进
为了将  GPU 检索能⼒⽆缝接⼊在线服务，我们的微信分布式向量检索系统  SimOL 采⽤了类

GPU 索引更新效率之间的⽭盾。
