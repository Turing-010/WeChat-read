2. 复盘：Agent迭代中   的  瓶颈与  优化

在持续的版本迭代中，我们发现多智能体协作虽显著提升了效率，但也暴露出⼀些典型问
题。这些问题集中在两个层⾯：准确率瓶颈、任务调度不均衡。

(1) 准确率的  瓶颈：上下⽂断流

在使⽤悟空 Agent 进⾏项⽬级扫描时，我们发现漏洞的准确率⾼度依赖上下⽂信息。⽽在
复杂代码项⽬中，⼤模型往往⽆法完整捕获输⼊输出的上下⽂链，造成“断流”现象。我们将
原因归纳为两点：

●框架复杂性导致上下⽂提取不⾜。 多层封装、动态 import、异步逻辑等模式，使得调
⽤链在语义层⾯被“截断”；

●内部特定代码⽤法缺乏知识覆盖。 某些⾃研框架或宏定义逻辑不在开源语料中，模型难
以正确解析。

针 对这两 类问题， 悟 空  Agent 团 队引⼊了 系统性的“上 下 ⽂ ⼯程（ Context
Engineering）”⽅案：

i) 增强上下⽂提取：

 通过专⽤上下⽂提取⼯具，针对类继承、装饰器逻辑、框架 Hook  等结构设定提取模板，
实现多层语义补全。

ii) 知识补全机  制 ：

 在识别到“内部专⽤调⽤”时触发 RAG-lik e 机制，从内部知识库实时检索相应逻辑并注⼊
上下⽂，使模型具备“局部知识回忆”能⼒。

经过持续优化后，Bad Case的归因命中率再次提升——多数误报都可在第⼆轮迭代中被消
化。

(2) 智能体调度失衡：协作退化为  串⾏

在多智能体架构下，理论上任务应在多个 Agent 间分⼯协作，但在实际运⾏中，我们发
现：

即使定义了各⾃Agent的职责与⼯具集，在解决⽤户需求的时候多个 Agent 仍倾向于让“主
Agent”独⾃处理任务。⽽不是将任务分发给不同职能的其他智能体来解决。





















这就带来了⼀个问题，原本是为了区分独⽴的上下⽂，从⽽提升⼦任务的解决效果⽽设计的
多智能体架构，退化为串⾏⼯具调⽤的单智能体架构，导致系统整体表现下降。

在进⾏⼤量调研后，我们后续计划通过强化学习（RL）调度机制解决该问题：

●采集少量⾼质量标注样本，训练模型识别任务场景与⻆⾊最优分配；

●让⼤模型学会在不同上下⽂中主动“移交任务”，⽽⾮被动等待指令；
