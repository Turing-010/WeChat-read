MCP 试图解决的是外部能⼒接⼊的标准化问题。
Anthropic  在  2024 年底发布了开放协议  Model Context Protocol （ MCP ），⽤统⼀⽅
式连接  AI 应⽤和外部数据源、⼯具。它为  AI 应⽤接⼊外部能⼒提供统⼀接⼝， Agent 不
需要分别适配每个系统的调⽤⽅式。
图： MCP 统⼀接⼊
多数⽤户对  MCP 的直接感知是 “Agent 多了⼀批可调⽤的⼯具 ” 。但它的名字是  Model
Context Protocol ⽽不是  Model Tools Protocol ，因为它提供的内容不限于⼯具。 MCP
Server 向  Agent 提供三种原语，关键差异在于谁来驱动：
• Resources （资源）：有  URI 标识、可读取的只读内容（⼀个⽂件、⼀条数据库记录、
⼀段实时数据）。它是应⽤  / Agent 驱动的 —— 由  Agent 或⽤户决定何时读取、注⼊，本
职⽤法是把读出的内容直接拼进  messages ，不经过  tool 。
• Tools （⼯具）：模型能调⽤的动作  / 函数。它是模型驱动的 —— 模型在推理时⾃⼰决定
是否调⽤。结果通常以  text 回流进上下⽂供模型继续推理，但也可以把
structuredContent 分流给  UI ⽽不进上下⽂。
• Prompts （提⽰模板）： Server 预先组织好、可复⽤的⼀组消息。它是⽤户驱动的 ——
由⽤户主动点选（如斜杠命令）触发，模板内部还能引⽤  resource ，把指令和⽂件内容打
包带⼊。
这三类原语说明， MCP 处理的不是单⼀的 “ ⼯具调⽤ ” ，⽽是  Agent 与外部系统之间的信
息、动作和提⽰模板如何被组织和传递。进⼀步看，外部系统返回的内容也不⼀定都要进
⼊模型上下⽂：有些内容适合给模型阅读，有些内容更适合直接展⽰给⽤户，或者让⽤户
在界⾯上确认和操作。

它包含五类动作，注意每个动作的精确含义：
