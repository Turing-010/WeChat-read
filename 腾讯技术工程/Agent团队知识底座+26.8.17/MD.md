⽆压⼒），⽽真正卡住的是两件事：

的那两三篇？纯⾃然语⾔写的长⽂，语义边界模糊，召回容易漂移。
第⼆，注⼊效率。就算找对了⽂档，⼀篇复盘⾥可能只有⼀段结论跟当前场景相关，你不可能

点容易⾛偏：不要把「给⼈看的知识」和「给  Agent 看的知识」做成两套东西。好的结构化
知识，⼈打开⼀样能读懂、能维护 —— 就像写得好的  Skill ⽂档或  Prompt ，⼈看起来也是清晰
的。反过来，如果⼀条知识⼈看着都觉得莫名其妙，它的维护质量也不会好，时间⼀长就腐败
了。所以我们的原则是⼈机共读：⼀套知识库，⼈和  Agent 都是消费者。
当  Agent 成为团队⼀线⽣产⼒，知识供给的问题随之暴露：检索不准、注⼊低效、过时
内容越堆越多。本⽂记录安全中⼼团队从定⽬标、搭体系到跑通知识飞轮的完整过程，包
括关键决策背后的思考、踩过的坑，以及可直接复⽤的⽅法。当团队开始⽤  Agent 做研
发和运营，⼀个问题很快浮出来：Agent 的输出质量，直接取决于你能给它什么质量的
知识。怎么让知识「产得出、找得准、喂得进、淘汰得掉」，是每个上了  Agent 的团队都
要解决的⼯程问题。本⽂章是基于团队搭建 AI 知识体系的实践，写建知识库整个过程的思
考、踩过的坑，以及可直接复⽤的⽅法。
