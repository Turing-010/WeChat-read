````text
⼀、 Jev 是什么：把⽣成问题改成判断问题
Jev 是  TypeSafe AI 发布的  System One Model 。它和我们熟悉的聊天模型不太⼀样：聊

原语 中⽂理解 输出形态 适合场景
````

````text
这和传统  summary 是两条不同路线。
传统  summary 的做法是把旧历史改写成⼀段短⽂本。优点是省  token ，缺点是路径、错误

它真正有意思的地⽅在于，它没有沿⽤ “ 让⼤模型总结历史 ” 的惯性，⽽是把上下⽂压缩拆成

keepCall ：这个⼯具调⽤本身还重要吗？
keepResult ：这个⼯具结果全⽂还需要保留吗？

⼀起删除。
fast-jev-compaction  是⼀个  Claude Code 插件，也可以作为  npm 库使⽤。它解决的
问题很窄：当会话需要  compact 时，不再把旧历史交给⼤模型总结，⽽是让  Jev 对历史⾥
的⼯具调⽤逐个打分，判断哪些应该原样保留，哪些只需要留下调⽤痕迹，哪些可以整体删
除。
它的核⼼约束是：⽤户⽂本和助⼿⽂本不改写；只处理⼯具调⽤和⼯具结果。
这个约束很重要。⽤户⽂本⾥通常有原始需求和硬约束，助⼿⽂本⾥有已承诺的计划和正在
执⾏的思路，这两类内容被摘要改写后容易变味。⼯具结果不同：它们占空间最⼤，也最容
易过期，⽽且很多内容可以重新读取或重新执⾏。
所以  fast-jev-compaction  不是 “ 总结器 ” ，⽽是 “ ⼯具历史清理器 ” 。它做的不是把历史改
````
