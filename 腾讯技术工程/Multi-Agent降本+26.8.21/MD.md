3.3.1 稳定前缀设计
KV Cache ：为什么前缀稳定等于省钱？
理解这个优化，需要先了解⼀点  Transformer 的底层机制。
LLM 处理每个  token 时，需要对它之前所有  token 做注意⼒计算（ Attention ），这个过程会产
⽣两个中间矩阵： K （ Key ）和  V （ Value ），合称  KV Cache 。 KV 矩阵的计算量是  O(n²)—— 这
是推理成本的主要来源。
Prompt Cache 的本质是：如果你本次请求的前缀和上次完全⼀致，服务商直接复⽤上次的
KV 矩阵，跳过重复计算，只收缓存读取的低价（约正常价格的  10% ）。
我们发现  「派发⼦  Agent 的提⽰词」⾥稳定指令和动态内容（技术⽅案⽂档）交错排列，导
致前缀⽆法命中缓存，改法是把动态内容统⼀后置。
主 Agent ⾃⾝还有个隐藏的前缀破坏者：进度状态不断在会话⾥输出累积。原来每个阶段切换
都要在对话⾥输出完整进度看板，堆积在历史⾥导致历史不能被压缩。改法是把进度状态外化
到⽂件中：
主 Agent 每次被唤醒先  read_ﬁle 进度⽂件，⽽不是回放历史。阶段切换也改成单⾏输出（ ✅
Wave 1 完成  →  Wave 2 🔄  已启动），额外收益是会话中断后可直接读⽂件恢复现场。
3.3.2 避免重复加载  Skill
