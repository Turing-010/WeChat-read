1. Model 是⼤脑。它有参数量、上下⽂窗⼝、多模态这些属性，但⼤脑再聪明，没有⼿脚也

系统， Model 只是它的⼀个部件。

API 还是脚本，它不需要知道。说得再直⽩⼀点， CLI 管⼯具怎么执⾏， MCP 管怎么把⼯具

五、 MCP 的实现形式
交流前客户做过功课，问我们  MCP 是不是有  stdio 、 HTTP 、 SSE 三种实现。对，但不全对。
这⾥有个连很多技术⽂章都搞错的事实。 MCP 官⽅规范⾥只有两种标准传输⽅式， stdio 和
Streamable HTTP 。 SSE 从  2025 年  3 ⽉起就被取代了，是历史⽅案。
完整的版图分四类。官⽅标准两种， stdio 和  Streamable HTTP ，默认选项。历史遗留⼀种，
HTTP 加  SSE ，只做存量迁移，别新建。社区扩展⼀批， WebSocket 、 WebRTC 、进程内
RPC ，这些是⽣态在标准之外长出来的，按需采⽤。
还有⼀类最容易混， MCP Gateway 、 Proxy 、托管  MCP ，它们属于部署架构，和新协议⽆
关，偏偏最容易跟传输⽅式搅在⼀起。⼀个认知先⽴住， MCP 是传输⽆关的，协议逻辑不

⼏种形式各说⼏句简要展开。
