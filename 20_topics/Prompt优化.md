## 先分清：改提示、改上下文、改系统、训练模型

Prompt优化要回答的是：在任务定义不变时，哪种表达和信息组织能稳定减少错误？它需要明确输入、期望输出和独立检验。更长、更像专家或写上“必须”都不是效果证据。

四个控制层应分开：提示规定任务与步骤；上下文流水线决定模型实际看见什么；解析器、工具和状态机决定哪些输出能够执行；训练修改模型参数。GEPA主要搜索文字参数，不是把Prompt优化叫成模型权重训练。风格微调、DPO、解码约束也不能混成同一项Prompt技巧。

## 评测把如实兜底判失败，要不要给Prompt加“必须给出答案”？

**来源主张。** art-0019把工具有数据与无数据分为不同回答模式，无数据时忠实兜底可以是正确行为；它区分数据、Judge Prompt、Rubric与Agent真实问题。art-0043让模型提出候选，由代码依实际评测结果选择基线、推进状态，避免生成者自行宣布达标。

**跨源归纳。** 假设售后助手查不到某商品的适用规则，旧提示回答“暂无可靠信息”，评测却因缺少具体条款判错。先回查当次工具结果和业务预期：确实无资料时，应修正评分契约中的空态要求，并保留修订理由；工具漏取资料时，则修数据链路。此时添加“任何情况都必须回答”可能把测量错误变成事实编造。候选提示仍可改善兜底表达，但应同时用有资料、真实空态、工具异常和原有成功样本比较，分别记录事实支持、正确拒答和新增退化，再按既定门禁决定接受或拒绝。

**条件与未知。** 兜底是否可接受须由该产品的任务契约决定，不能从购物案例外推所有业务。若评分规则也变了，应在同一规则版本下重评新旧提示；分数因纠正误判上升不等于提示能力提升。这里提供诊断顺序，未运行优化器或证明任一固定阈值适合当前项目。

## 六个共同知识点

| 知识点 | 多篇合起来能学到什么 | 适用条件与边界 |
| --- | --- | --- |
| 把目标写成输入与输出契约 | art-0312用样本、期望结果、错误说明迭代；art-0246把“保持一致”细化为复用哪个组件、旧位置是否删除；art-0203把已确认语义与设计作为生码输入 | 模型能理解的说明与机器能强制执行的约束不同。缺事实要标未知，不能靠措辞填补 |
| 提示和上下文共同设计 | art-0291将取数、检索和格式化放到调用前；art-0259区分当前事实与操作历史；art-0004/0114按任务保留状态 | 摘要有损，旧文件快照可能过期；长度、位置和重复次数要实测，没有固定通用最优值 |
| 检查的是语义与证据，不只形式 | art-0266区分解码约束、风格和偏好；art-0254区分相关、正确、完整；art-0051用事实身份与内容块验证代替句长配额 | JSON合法仍可数值错误，引用存在仍可不支持结论。偏好也不等于事实正确 |
| 修坏例时保住好例 | art-0289修一条env_file案例却破坏五条原好例；art-0025逐例对齐修复与新增错；art-0043把坏例与非重叠近期样本分开评估 | 总分上升可能掩盖关键退化；反复用于选择的验证集不能再当独立终评 |
| 模型提候选，系统决定是否接受 | art-0011通过轨迹反思、变异、评分与候选选择搜索；art-0043由代码管阈值、早停和入库；art-0012显示换序稳定与判断正确必须分测 | 优化器会适应评价标准，错误标签或错误评分会把系统带向错误目标 |
| 先定位错误层，再决定改哪里 | art-0019区分数据、Prompt、Rubric和Agent问题；art-0051区分检查器误报、数值引用和判断错误 | 不能每次低分都加一条Prompt；改评价尺子与改被评系统要分别记录，延迟与成本也要测 |

### 一个最小例子：优惠风险检查

假设任务是判断SKU组合是否触发破价。应先固定活动规则、货币精度、商品范围和基准价来源，再规定输出包含输入ID、判定、所用证据和缺失字段。价格计算交给确定性程序，模型可以解释规则和安排查询；这正是art-0248适合继续工程化的边界。

出现失败后，先分类：基准价没取到是数据或工具问题；计算错是算法/计算链路问题；输出缺ID是契约问题；评分把未知当安全是评价问题。修补一个提示版本时，同时跑正常、边界、数据缺失、解析失败和原来做对的案例。不能用空对象表示“无风险”，也不能靠提高Judge宽容度证明风险系统变好。

## 各篇独特贡献与取舍

| 来源 | 对共同知识点的补充 | 学习时不应扩大到哪里 |
| --- | --- | --- |
| art-0312 | 用约30条样本启动迭代，并同步修改步骤、示例和上下文说明 | 30是经验起点；部分示例缺图，没有独立泛化评测 |
| art-0001 | 问题重构、横向比较、钢人论证可作为提示模板的任务目标 | 角色设定不产生专业能力；模板本身不是效果实验 |
| art-0291 | 工具结果到来后设置显式检查步骤，区别于只写初始提示 | 结构化日志不是读取内部思维，也不是形式化正确性证明 |
| art-0284 | 从前三版先贴风险标签，改成第四版先提具体问题、据文回答、最后分类 | 原文p.34明确案例、场景和数据均虚构，只学设计取舍，不引用为生产收益 |
| art-0259 | 刷新当前文件事实、保留调用历史，关闭文件前按阅读目的摘取备忘 | open/close与消息重组需要宿主实现，不是写进提示就生效 |
| art-0114、art-0004 | 显式检查点与外部笔记帮助继续工作，按需装载减少无关材料 | 长摘要可能丢信息；当前记忆状态和恢复位置需要核对 |
| art-0184 | 动态事实、稳定规则与缓存成本一起考虑；实际请求量需要可观测 | 个别provider的缓存TTL不能外推所有模型；少token不一定低总成本 |
| art-0005 | 将范围、编码和交付偏好写成仓库规则，便于持续引用 | 文件存在不保证宿主一定载入或每轮遵守，仍需实际验收 |
| art-0203 | 已确认的需求、资源和设计分阶段传递，最后提示保留必要上下文 | 文件有内容不代表已确认或不可变，变更需要同步下游 |
| art-0246 | 局部页面问题要看父布局与实际依赖版本，并回归兄弟组件 | 更多上下文不能代替定位根因；最新版文档未必适用项目旧版 |
| art-0266 | 风格示例、逆向构造中性文本与偏好对提供不同改造方式 | 合成配对要核保真；微调与解码约束属于不同控制层 |
| art-0254 | 引用必须支持当前断言，检索判别器也可能判断错 | 多加一个Judge不自动获得独立真值 |
| art-0248 | 参数化模板、版本灰度和业务字段让调用方复用任务契约 | 自然语言封装没有消灭系统复杂度，算术及失败处理仍需工程实现 |
| art-0289 | 用具体的“一例修好、五例变坏”说明为什么需要回归集 | 调用轨迹全绿、lint通过都不等于业务任务成功 |
| art-0025 | 把候选补丁、逐例指标、拒绝原因和失败记忆绑定到版本 | 原文部分结果表GT数量变化，不能直接合成固定标签集的提升结论 |
| art-0043 | 改写候选与接受门禁分开，规则定义不能为涨分偷偷改变 | 固定阈值要结合样本量；一次过门禁仍不等于长期可靠 |
| art-0011 | GEPAService从各业务手写适配转为任务类型配置，训练/验证/终评分开 | 内部2.0不是GEPA原算法版本；冻结区、长度治理和无真值策略优化部分仍是展望 |
| art-0012 | A/B位置随机化暴露虚高，80%一致但55%正确说明稳定地错也可能发生 | 全数据先挖规则再交叉验证仍会泄漏，需外层独立数据评整条选择流程 |
| art-0051 | 撤销固定议题配额、句长和关键词黑名单，转向方法与事实绑定 | 允许自然表达依赖后续验证，不等于取消约束；各阶段没有精确日期 |
| art-0019 | 评测需检查日志清洗、枚举映射和分子分母；调Rubric与修Agent分开归因 | 通过率提高可能仅因纠正了误判，不能自动写成Agent能力提高 |
| art-0185 | 对字段、规则和CoT做消融，同时衡量准确率、Prefill、Decode和真机体验 | 此端侧场景最终放弃简版提示；“提示越短越好”不成立 |

## 当前适用性与官方核查（2026-10-23）

- **仍适用：反思式文字搜索。** GEPA当前官方仓库支持通过适配器提供评价与反思数据，并可优化多类文字参数；库内GEPAService属于业务封装，不能等同于官方API。原论文首版2025-07-25、第二版2026-02-14；本文没有复现其性能结论。[官方仓库](https://github.com/gepa-ai/gepa) · [论文与版本历史](https://arxiv.org/abs/2507.19457)
- **已变化：独立think工具并非现在默认必需。** Anthropic在2025-12-15更新原文，建议大多数情形使用extended thinking。保留历史的“工具返回后检查约束”思想，具体实现按模型能力选择；不能把旧标题的“必然”当当前产品要求。[官方更新](https://www.anthropic.com/research/claude-think-tool)
- **需纠正：禁止token不能仅把logit设为0。** 当前Transformers的SuppressTokensLogitsProcessor采用负无穷抑制；有限的0经softmax仍有正概率。语法限制和业务语义正确仍是两层检查。[官方生成文档](https://huggingface.co/docs/transformers/internal/generation_utils#transformers.SuppressTokensLogitsProcessor)
- **尚不能确认：内部平台通用收益与当前功能状态。** 本库没有这些平台可运行代码、完整实验配置或当前租户功能验证；保留机制和版本条件，不把截图数字推广到所有模型与团队。

2. GEPA反思认为原因是提示不清，这是否已证明错误来自Prompt？
